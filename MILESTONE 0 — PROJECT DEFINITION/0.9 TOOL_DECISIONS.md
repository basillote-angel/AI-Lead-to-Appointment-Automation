# Voryn — Tool & Technology Decisions

## Project
AI Lead-to-Appointment Automation

## Milestone
0.9 — Tool & Technology Decisions

## Decision Principles

Tools are selected based on:

1. Project requirements
2. Learning value
3. Real-world client usefulness
4. Cost
5. Maintainability
6. Portfolio value
7. Ability to scale later

## Selected MVP Stack

### Automation
n8n

Purpose:
Workflow orchestration and automation.

Reason:
Already available locally, strong automation capabilities, webhook/API support, and useful for Automation VA work.

### Database
Supabase / PostgreSQL

Purpose:
Persistent lead and workflow data storage.

Reason:
Provides PostgreSQL database capabilities through a free tier and teaches transferable database skills.

### AI
Gemini API

Purpose:
Lead analysis, structured extraction, classification assistance, and response generation.

Reason:
Provides a suitable developer API with a free tier for initial learning and experimentation.

### Appointment Scheduling
Calendly Free

Purpose:
Appointment booking and scheduling.

Reason:
Provides a simple free scheduling capability suitable for the MVP.

### Lead Capture
Simple form + n8n Webhook

Purpose:
Capture and send lead information into n8n.

Reason:
Provides direct experience with webhooks and HTTP-based automation.

### Development
VS Code

Purpose:
Documentation, development, configuration, and code.

### Version Control
Git + GitHub

Purpose:
Version control, backup, collaboration, and portfolio presentation.

## Secondary / Future Tools

### Google Sheets

Will be learned as an important VA-friendly data and reporting tool, but it is not the primary database for the MVP.

### Google Calendar API

May be introduced later to teach direct calendar API integration.

### CRM integrations

May be introduced after the MVP.

## Budget Strategy

During learning and MVP development:

- Prefer free/local tools.
- Avoid unnecessary subscriptions.
- Use free tiers where appropriate.
- Introduce paid production tools only when they provide a real project requirement.

## Important Principle

The objective is not to learn as many tools as possible.

The objective is to learn transferable automation concepts and apply appropriate tools to solve business problems.
