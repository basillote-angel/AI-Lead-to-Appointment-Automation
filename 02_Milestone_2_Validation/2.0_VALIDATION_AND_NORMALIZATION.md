# Milestone 2 — Validation and Normalization

## Objective

Protect the workflow from incomplete or malformed lead submissions before we store or analyze them.

The workflow will:

1. Receive the lead from the Webhook.
2. Trim unnecessary spaces.
3. Normalize values such as email and service.
4. Validate required fields.
5. Return a clear success or error response.

We use deterministic rules here. AI is not needed for basic validation.

## Concepts

- **Validation:** checking whether data meets a rule.
- **Normalization:** converting acceptable data into a consistent format.
- **Required field:** information the workflow cannot continue without.
- **HTTP 400:** a response meaning the request contains invalid data.

## Validation Rules for MVP

Required:

- `name`
- `email`
- `message`

Optional:

- `phone`
- `company`
- `service`
- `budget`
- `timeline`

Allowed services when provided:

- `Website Design/Development`
- `Website Redesign`
- `E-commerce Website`
- `Basic Digital Marketing`

The demo form currently uses `E-commerce Website`.

## n8n Workflow

```text
Webhook
   ↓
Code — Validate and Normalize
   ↓
Respond to Webhook
```

### Webhook node

Keep the existing settings:

- Method: `POST`
- Path: `voryn-lead`
- Respond: `Using Respond to Webhook Node`

### Code node

Add a **Code** node after the Webhook. Set **Mode** to `Run Once for All Items`, then paste this code:

```javascript
const webhookData = $input.first().json;
const input = webhookData.body ?? webhookData;

const text = (value) => String(value ?? '').trim();
const name = text(input.name);
const email = text(input.email).toLowerCase();
const phone = text(input.phone);
const company = text(input.company);
const service = text(input.service);
const budget = text(input.budget);
const timeline = text(input.timeline);
const message = text(input.message);

const allowedServices = [
  'Website Design/Development',
  'Website Redesign',
  'E-commerce Website',
  'Basic Digital Marketing'
];

const errors = [];
if (!name) errors.push('name is required');
if (!email) errors.push('email is required');
if (email && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
  errors.push('email must be valid');
}
if (!message) errors.push('message is required');
if (service && !allowedServices.includes(service)) {
  errors.push('service is not an allowed Voryn service');
}

return [{
  json: {
    valid: errors.length === 0,
    errors,
    lead: {
      name,
      email,
      phone,
      company,
      service,
      budget,
      timeline,
      message
    }
  }
}];
```

The Code node does not decide whether the lead is HOT or WARM. That belongs to later qualification logic.

### Respond to Webhook node

Open the existing **Respond to Webhook** node:

- Respond With: `JSON`
- Response Code: use this expression:

```text
{{ $json.valid ? 200 : 400 }}
```

- Response Body: use this expression:

```text
{{ $json }}
```

A valid response will look like:

```json
{
  "valid": true,
  "errors": [],
  "lead": {
    "name": "Maria Santos",
    "email": "maria@example.com"
  }
}
```

An invalid response will look like:

```json
{
  "valid": false,
  "errors": [
    "email must be valid",
    "message is required"
  ],
  "lead": {
    "name": "Maria Santos",
    "email": "not-an-email"
  }
}
```

## Test Checklist

### Test 1 — Valid lead

Use the existing Maria Santos sample. Expected result:

- HTTP status `200`
- `valid` is `true`
- Email is lowercase
- Extra spaces are removed
- `errors` is empty

### Test 2 — Invalid lead

Temporarily change the form values to:

- Email: `not-an-email`
- Message: empty

Expected result:

- HTTP status `400`
- `valid` is `false`
- `errors` lists both problems
- The workflow does not silently accept the lead

### Test 3 — Unsupported service

Set service to `Logo Design`. Expected result:

- HTTP status `400`
- `errors` includes `service is not an allowed Voryn service`

## Definition of Done

- [x] Code node is connected after Webhook.
- [x] Valid lead returns HTTP `200`.
- [x] Invalid lead returns HTTP `400`.
- [x] Normalized values appear in the output.
- [x] Validation errors are visible in the response.
- [x] No AI or database nodes are used yet.
