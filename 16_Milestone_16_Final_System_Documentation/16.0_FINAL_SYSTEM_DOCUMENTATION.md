# Milestone 16 — Final System Documentation

## Objective

Assemble a client-ready documentation package that explains what the Voryn automation does, how it is configured, how it is tested, how it is deployed, and how an authorized operator maintains and troubleshoots it.

M16 packages verified project evidence. It must not describe planned behavior as if it were implemented.

## Documentation Audience

### Client or business owner

Needs to understand:

- the business problem and expected outcome
- what the automation handles
- where human approval remains required
- what happens when a lead books, responds, or fails
- what information is stored
- who owns operations and escalation

### Operator or automation maintainer

Needs to understand:

- how to configure credentials safely
- how to activate and pause workflows
- how to inspect executions and error logs
- how to test changes
- how to restore or roll back
- how to rotate credentials and maintain providers

### Developer or reviewer

Needs to understand:

- architecture and data flow
- schema and status contracts
- workflow inputs and outputs
- AI validation boundaries
- idempotency and retry behavior
- security decisions and known limitations

## 16.10 Troubleshooting Guide

Use symptom-to-action entries:

| Symptom | First checks | Likely causes | Safe action |
| --- | --- | --- | --- |
| Webhook returns `400` | response errors and input fields | invalid or incomplete lead | correct input; do not bypass validation |
| Lead is not stored | n8n execution and Supabase node | validation, credential, or constraint failure | inspect execution and error log |
| AI fields are empty | Gemini node and parser output | timeout, malformed JSON, missing field | retry if transient; route to review |
| No approval email | email node and recipient config | SMTP failure or invalid recipient | verify delivery and retry separately |
| Follow-up does not fire | `next_follow_up`, wait, and status | timing mismatch or stop condition | re-read state before replaying |
| Appointment is not booked | Calendly response and lead email | polling window or match failure | do not mark booked manually without evidence |
| Duplicate appointment action | provider event ID and lead row | idempotency defect | stop replay and reconcile state |
| Confirmation missing | booking row and email execution | notification failure | preserve booking; retry confirmation independently |
| Error alert missing | Error Trigger and log write | sequential fallback failure | preserve execution evidence and escalate |
| Reminder sent incorrectly | appointment status and time zone | stale state or test delay | stop reminder path and reconcile appointment |

Never include secrets in troubleshooting screenshots or copied error messages.
