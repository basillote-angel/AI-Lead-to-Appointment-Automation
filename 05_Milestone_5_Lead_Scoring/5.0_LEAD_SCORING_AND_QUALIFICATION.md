# Milestone 5 — Lead Scoring and Qualification

## Objective

Apply a clear, repeatable business rubric to the stored lead and AI analysis, then classify the lead as `HOT`, `WARM`, or `NEEDS_INFORMATION`.

Milestone 4 interpreted the message. This milestone makes the business-rule decision using deterministic n8n logic.

## Architecture Boundary

- Validation remains deterministic and belongs to Milestone 2.
- Storage remains the source of truth and belongs to Milestone 3.
- AI interpretation belongs to Milestone 4.
- Scoring and classification belong to Milestone 5.
- Do not ask AI to make the final qualification decision.
- Do not add `lead_score` or `lead_classification` columns; they already exist in the Milestone 3 table.

## Scoring Rubric

| Factor | Condition | Points |
| --- | --- | ---: |
| Service fit | Requested service matches a Voryn service | +25 |
| Budget | Budget is provided | +20 |
| Timeline | Timeline is provided | +20 |
| Urgency | AI analysis says `high` | +20 |
| Information quality | Message contains at least 30 characters | +15 |

Maximum score: `100`.

### Classification Rules

- `HOT`: score `70` or higher and no important information gap.
- `WARM`: score `40` to `69`, or score `70` or higher with important missing information.
- `NEEDS_INFORMATION`: score below `40`, or insufficient information to assess fit.

A lead with insufficient information needs clarification rather than automatic rejection.

## Workflow

Add scoring after the AI analysis has been stored or returned:

```text
Supabase — Get Lead and Analysis
   ↓
Code — Calculate Score
   ↓
Supabase — Update Qualification
   ↓
Respond to Webhook or Continue to Routing
```

The existing invalid-lead path remains unchanged and must bypass scoring.

## Step 1 — Prepare the input

The scoring Code node needs:

- Original `service`
- Original `budget`
- Original `timeline`
- Original `message`
- AI `service_fit`
- AI `urgency`
- AI `missing_information`

Use n8n's expression picker if your field paths differ.

## Step 2 — Add the scoring Code node

Add a **Code** node after the AI analysis/update step. Set it to **Run Once for All Items**.

This example expects the lead and analysis under `$json`. Adjust only the input paths if your previous Supabase node returns a different shape.

```javascript
const item = $input.first().json;
const lead = item.lead ?? item;
const analysis = item.analysis ?? item;

const service = String(lead.service ?? analysis.service_fit ?? '').trim();
const budget = String(lead.budget ?? analysis.budget ?? '').trim();
const timeline = String(lead.timeline ?? analysis.timeline ?? '').trim();
const message = String(lead.message ?? '').trim();
const urgency = String(analysis.urgency ?? '').trim().toLowerCase();
const missingInformation = Array.isArray(analysis.missing_information)
  ? analysis.missing_information
  : String(analysis.missing_information ?? '').trim()
      .split(',')
      .map((value) => value.trim())
      .filter(Boolean);

const allowedServices = [
  'Website Design/Development',
  'Website Redesign',
  'E-commerce Website',
  'Basic Digital Marketing'
];

let score = 0;
if (allowedServices.includes(service)) score += 25;
if (budget) score += 20;
if (timeline) score += 20;
if (urgency === 'high') score += 20;
if (message.length >= 30) score += 15;

const hasImportantGaps = missingInformation.length > 0;
let leadClassification;
if (score < 40) {
  leadClassification = 'NEEDS_INFORMATION';
} else if (score >= 70 && !hasImportantGaps) {
  leadClassification = 'HOT';
} else {
  leadClassification = 'WARM';
}

return [{
  json: {
    lead_id: lead.lead_id ?? item.lead_id,
    lead_score: score,
    lead_classification: leadClassification,
    scoring_reasons: {
      service_fit: allowedServices.includes(service),
      budget_provided: Boolean(budget),
      timeline_provided: Boolean(timeline),
      high_urgency: urgency === 'high',
      useful_message: message.length >= 30,
      missing_information: missingInformation
    }
  }
}];
```

## Step 3 — Update Supabase

Use the existing `lead_id` to update the same row.

Set:

- `lead_score` from `{{ $json.lead_score }}`
- `lead_classification` from `{{ $json.lead_classification }}`
- `status` to `QUALIFIED`

Do not overwrite the original customer-provided fields or AI analysis fields.

## Test Checklist

### Test 1 — High-potential lead

Use the Maria Santos lead with its budget, 30-day timeline, matching service, detailed message, and high urgency analysis.

Expected:

- Score is calculated deterministically.
- Classification is `HOT` unless important information is missing.
- The existing row is updated, not duplicated.
- Original lead and AI fields remain intact.
- Status becomes `QUALIFIED`.

### Test 2 — Partial-information lead

Use a supported service and useful message but no budget or timeline.

Expected:

- Score is lower than the complete lead.
- Classification is `WARM` or `NEEDS_INFORMATION` according to the rubric.
- The lead is not automatically rejected.
- Missing information is visible in the scoring reasons.

### Test 3 — Very low-information lead

Use a vague message with no useful service, budget, or timeline information.

Expected:

- Score is below `40`.
- Classification is `NEEDS_INFORMATION`.
- The original record remains available for follow-up.

### Test 4 — Repeatability

Run the same lead through the scoring node twice.

Expected:

- Score and classification are identical both times.
- No AI call is required for the scoring decision.
