# Milestone 4 — AI Lead Analysis

## Objective

Use Gemini to interpret the lead's natural-language message and return structured analysis for later business rules.

This milestone does not make the final HOT/WARM/NEEDS_INFORMATION qualification decision. AI extracts meaning; later deterministic logic in Milestone 5 will apply the qualification rubric.

## Database Preparation

Milestone 4 requires additional columns in the existing Supabase `leads` table. The Milestone 3 table already contains the original lead, workflow, follow-up, and appointment fields. Run this migration before adding the Gemini workflow:

```sql
ALTER TABLE leads
ADD COLUMN ai_summary TEXT,
ADD COLUMN business_type TEXT,
ADD COLUMN intent TEXT,
ADD COLUMN missing_information TEXT,
ADD COLUMN ai_confidence NUMERIC;
```

This migration:

1. Modifies the existing `leads` table.
2. Does not recreate or delete the table.
3. Keeps existing lead records intact.
4. Leaves the new fields as `NULL` initially.
5. Allows the fields to be populated after Gemini analyzes a lead.

Do not add `lead_score` or `lead_classification` again. Those columns already exist and belong to Milestone 5.

The `missing_information` value will be stored as text in this milestone. If Gemini returns an array, serialize that array as JSON text before saving it.

## Concepts

- **Prompt:** instructions and context sent to an AI model.
- **Structured output:** predictable fields instead of a paragraph.
- **Confidence:** the model's estimate of how clear the analysis is.
- **AI boundary:** AI interprets language, while n8n and business rules control workflow decisions.

## Workflow

Extend the valid path from Milestone 3:

```text
Supabase — Insert Lead
   ↓
Gemini — Analyze Lead
   ↓
Code — Parse AI Result
   ↓
Supabase — Update Lead Analysis
   ↓
Respond to Webhook
```

Keep the invalid path connected directly to the existing response node.

The invalid path from Milestone 3 remains unchanged: invalid leads bypass Gemini and storage updates, then return the existing validation response.

## Step 1 — Add Gemini credentials

1. Add a Gemini or Google Gemini node available in your n8n installation.
2. Create credentials through n8n's credential manager.
3. Do not paste the API key into a Code node, this document, or a Git commit.
4. Use a low-cost/free-tier model suitable for testing.

If your n8n version does not have a Gemini node, use an HTTP Request node with the official Gemini API and store the key in n8n credentials. Do not put the key in the URL or committed workflow JSON.

## Step 2 — Build the analysis prompt

Send the lead fields to Gemini. Use expressions from the Supabase/Code data available in your workflow.

Use this prompt:

```text
You analyze incoming service-business leads for Voryn Studio, a web design and digital marketing agency.

Analyze the lead below. Extract only information supported by the lead. Do not invent pricing, services, dates, or customer facts.

Return ONLY valid JSON with exactly these fields:
{
  "summary": "brief factual summary",
  "business_type": "business type or unknown",
  "intent": "main customer goal",
  "service_fit": "one of: Website Design/Development, Website Redesign, E-commerce Website, Basic Digital Marketing, Unknown",
  "budget": "stated budget or unknown",
  "timeline": "stated timeline or unknown",
  "urgency": "one of: high, medium, low, unknown",
  "missing_information": ["list of useful missing details"],
  "confidence": 0.0
}

Lead:
Name: {{ $json.lead.name }}
Company: {{ $json.lead.company }}
Service: {{ $json.lead.service }}
Budget: {{ $json.lead.budget }}
Timeline: {{ $json.lead.timeline }}
Message: {{ $json.lead.message }}
```

The exact field names may differ depending on the Gemini node. Use the expression picker in n8n rather than typing a guessed path if the node input comes from Supabase.

## Step 3 — Inspect the AI output

Execute the Gemini node with the Maria Santos lead. Look for the model's text response.

A successful result should contain JSON similar to:

```json
{
  "summary": "Santos Coffee wants an e-commerce website for its coffee business.",
  "business_type": "coffee shop",
  "intent": "build an online store",
  "service_fit": "E-commerce Website",
  "budget": "100000",
  "timeline": "30 days",
  "urgency": "high",
  "missing_information": ["required features", "preferred payment methods"],
  "confidence": 0.9
}
```

Do not worry if the wording differs. Check that the output is factual, complete, and machine-readable.

## Step 4 — Parse and protect the result

If Gemini returns JSON as text, add a Code node after it to parse the response. First inspect the Gemini node output because the response path varies by n8n node version.

The parser should convert the text into fields named:

- `ai_summary`
- `business_type`
- `intent`
- `missing_information`
- `ai_confidence`

Reject or escalate output that is not valid JSON, has missing required analysis fields, or has confidence outside `0` to `1`. Do not silently save malformed AI output.

## Step 5 — Update Supabase

Update the existing lead record using its database-generated `lead_id`.

Set:

- `ai_summary` from `summary`
- `business_type` from `business_type`
- `intent` from `intent`
- `missing_information` from `missing_information`
- `ai_confidence` from `confidence`
- `status` to `ANALYZED`

Keep the original customer-provided fields unchanged.

## Test Checklist

### Test 0 — Database preparation

Run the migration in Supabase SQL Editor and confirm that the existing `leads` table now includes:

- `ai_summary`
- `business_type`
- `intent`
- `missing_information`
- `ai_confidence`

Expected:

- Existing lead rows remain present.
- The new fields are `NULL` before AI analysis.
- `lead_score` and `lead_classification` are not duplicated.

### Test 1 — Clear lead

Use the Maria Santos lead.

Expected:

- Gemini returns structured JSON.
- Summary reflects the customer's request.
- Service fit is `E-commerce Website`.
- Budget and timeline are preserved.
- Confidence is between `0` and `1`.
- The database record changes to `ANALYZED`.

### Test 2 — Incomplete lead

Use a valid lead with a vague message such as `I need help with my business website.`

Expected:

- AI identifies missing information.
- AI does not invent a budget or timeline.
- The record remains traceable.

### Test 3 — AI failure

Temporarily disable the Gemini credential or use a controlled failure test.

Expected:

- The failure is visible in the n8n execution.
- The lead is not silently lost.
- The lead can be escalated or retried later.
