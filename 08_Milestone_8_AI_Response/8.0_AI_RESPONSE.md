# Milestone 8 — AI-Assisted Customer Response

## Objective

Generate a personalized draft response for a qualified lead while requiring human approval before any customer-facing message is sent.

This milestone drafts communication. It does not send automatically, negotiate, invent business information, or replace human judgment.

## Architecture Boundary

- Validation belongs to Milestone 2.
- Storage belongs to Milestone 3.
- AI analysis belongs to Milestone 4.
- Scoring belongs to Milestone 5.
- Routing and internal notifications belong to Milestones 6 and 7.
- Response drafting belongs to Milestone 8.
- Follow-up automation belongs to Milestone 9.
- Human approval is required before sending important customer communication.

## Workflow

Continue from the qualified and routed lead:

```text
Routed Lead
   ↓
Gemini — Draft Response
   ↓
Code — Validate Draft
   ↓
Human Review / Approval
   ↓
Approved draft continues to sending in a later step
```

Do not connect the draft directly to an email-sending node without an approval step.

## Step 1 — Build the draft prompt

Use the lead's original information, AI analysis, qualification, and route. Use approved business facts only.

```text
You draft customer responses for Voryn Studio, a web design and digital marketing agency.

Write a concise, professional, helpful response to the lead below.

Rules:
- Use only the facts provided below.
- Do not invent prices, delivery promises, services, discounts, or availability.
- Do not negotiate.
- Do not claim that an appointment is booked.
- Acknowledge the customer's request.
- Mention useful missing information when appropriate.
- Suggest the next step based on the route.
- Keep the tone warm and professional.
- Return only the draft message text, with no analysis or markdown headings.

Lead name: {{ $json.name }}
Company: {{ $json.company }}
Service: {{ $json.service }}
Budget: {{ $json.budget }}
Timeline: {{ $json.timeline }}
Original message: {{ $json.message }}
AI summary: {{ $json.ai_summary }}
Missing information: {{ $json.missing_information }}
Classification: {{ $json.lead_classification }}
Route: {{ $json.route }}
Recommended action: {{ $json.next_action }}
```

## Step 2 — Validate the draft

Add a Code node after Gemini. Check that:

- The draft is not empty.
- The draft is text.
- It does not contain obvious internal instructions or analysis.
- It does not claim that an appointment is already booked.

If the draft fails validation, stop the workflow and send it for manual review. Do not send the failed draft.

## Step 3 — Human approval

For the first version, use a manual approval method such as:

- An n8n approval step, if available.
- An internal email containing the draft and an approval link or instruction.
- A manual workflow execution after reviewing the draft.

The reviewer should check:

- The customer name and request are correct.
- No unsupported price or promise was added.
- Missing information is requested politely.
- The next step is appropriate.
- The message is safe to send.

## Test Checklist

### Test 1 — HOT or priority lead

Expected:

- A relevant draft is generated.
- The draft suggests the approved next step.
- No appointment is claimed as already booked.
- Human approval is required.

### Test 2 — WARM lead

Expected:

- The draft politely requests missing details.
- The draft does not reject the lead.
- Human approval is required.

### Test 3 — NEEDS_INFORMATION lead

Expected:

- The draft asks clear clarification questions.
- No unsupported business information is invented.
- Human approval is required.

### Test 4 — Invalid lead

Expected:

- The invalid lead path does not generate a customer response draft.

### Test 5 — Unsafe or malformed draft

Expected:

- The draft is stopped or escalated.
- No customer-facing message is sent.

## Definition of Done

- [ ] Gemini generates a personalized draft using lead context.
- [ ] The draft uses approved business information only.
- [ ] Draft validation rejects empty or unsafe output.
- [ ] HOT, WARM, and NEEDS_INFORMATION drafts are tested.
- [ ] Invalid leads bypass response drafting.
- [ ] Human approval is required before sending.
- [ ] No draft claims an appointment is already booked.
- [ ] No automatic customer-facing send occurs before approval.
